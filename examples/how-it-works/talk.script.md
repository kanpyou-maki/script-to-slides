# 台本からスライドができるまで

📊 P1 — 台本からスライドができるまで（タイトル）

script-to-slides は、話す台本から、図解主体のスライドを作る Claude Code のプラグインです。
この話では、台本がスライドになるまでの仕組みを、4つの段階で紹介します。

---

📊 P2 — 台本が先、スライドはあと（1/3）

出発点は、話す内容を書いた台本です。
台本には、ページを送る位置に「📊」の注記を書いておきます。

📊 P3 — 台本が先、スライドはあと（2/3）

Claude は台本を読んで、ページ割りを決め、デッキと図のコードを書きます。
デッキは Marp の Markdown、図は Python のコードです。

📊 P4 — 台本が先、スライドはあと（3/3）

最後に、書き出しの道具が図を SVG にして、PDF とページ画像を作ります。
スライドの文字は、すべて台本から導きます。

---

📊 P5 — 図はコードで描いて、測って確かめる（1/3）

図は、段階の番号を受け取る Python の関数として書きます。
同じ図を数枚に割って、話に合わせて要素を足していきます。

📊 P6 — 図はコードで描いて、測って確かめる（2/3）

書き出した図は、ブラウザで描画して実測します。
見るのは、箱の縁までの余白、はみ出し、小さすぎる文字などです。

📊 P7 — 図はコードで描いて、測って確かめる（3/3）

NG が出たら、図のコードに戻って直します。
文字の幅は目で見積もらず、通るまで測り直します。
通ったら、デッキに貼ります。

---

📊 P8 — 台本とページを機械で照合する（1/2）

次に、台本の注記とデッキのページを、道具が照合します。
注記の数とページ数、見出し、段階の番号がそろっているかを見ます。

📊 P9 — 台本とページを機械で照合する（2/2）

まとめのページは、台本のまとめと一字一句そろっているかを確かめます。
1文字でも違えば NG になります。

---

📊 P10 — 別のエージェントがレビューする（1/2）

仕上げに、書き手とは別のエージェントにレビューさせることを勧めています。
レビュアーは、台本との整合、図の規則、描画した見た目を確かめて、PASS か BLOCK を返します。

📊 P11 — 別のエージェントがレビューする（2/2）

BLOCK なら、書き手が直して、同じレビュアーにもう一度見てもらいます。
PASS したら、あなたに渡します。

---

📊 P12 — まとめ

## まとめ

1つ目、台本が先にあり、スライドの文字は台本から導くこと
2つ目は、図はコードで描き、ブラウザで描画して実測してから使うこと
3つ目は、台本とページの対応とまとめを道具が照合し、別のエージェントがレビューすること
