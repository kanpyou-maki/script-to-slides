# 台本から、図解主体のスライドを作る

台本（話す内容）が先にあり、スライドはそれを話しているときに映す補助資料、という前提で作る。
内容のページは「見出し＋図1つ」にし、同じ図を数ページに割って要素を足していく（段階表示）。

規則の本文は `references/` にある。必要になった時点で読む:

| ファイル | 読むとき |
|---------|---------|
| `references/setup.md` | 最初に1回（道具の準備・ファイルの置き方） |
| `references/consistency.md` | 台本を読むとき・台本を調整するとき（📊 注記の書き方・文字は台本から導く・まとめの照合） |
| `references/figures.md` | 図を描くとき（図の規則・色・検査に出ないもの） |

道具はこの skill の `scripts/` にある（以下 `<skill>/scripts/`）。コマンドを手で組まない（marp を直接呼ぶと、標準入力待ちで止まることがある）。

## 0. 準備（そのフォルダで初めてのときだけ）

1. `references/setup.md` のとおり、`<skill>/assets/` の `theme.css`・`components.css`・`figlib.py` をデッキの上の階層に写す
2. 台本がなければ、ユーザーに書いてもらうか、一緒に書く。台本の形は `references/consistency.md` の「台本の書き方」、見本は `<skill>/../../examples/hand-drip/`

## 1. 台本を読み、ページ割りを決める

1. 台本の段落の順序を読む。`📊` 注記があれば、`python3 <skill>/scripts/check_deck.py <デッキ.md> --table` で対応表を出す（デッキがあるとき。手で列挙しない）
2. 段落ごとに「図にする関係（流れ・対比・包含・時系列）」があるかを決める。なければ台本の語句を大きく1〜2行で置く
3. 仕組みの図は、読み上げ1〜2文ごとに1段階として、何枚に割るかを決める

## 2. 図を描く

- デッキの隣に `<デッキ名>_figs.py` を作る（見本: `examples/hand-drip/talk_figs.py`）。図は段階の番号を受け取る関数にする
- 部品は `figlib.py` の冒頭の一覧から選ぶ。似た見た目をその場で作らず、足りなければ `figlib.py` に部品を足す
- 冒頭の説明に、図の骨組み・色の割り当て・図だけに足したものを書く（あとで直す人が読む）
- `references/figures.md` の規則を守る

## 3. デッキを書き、ビルドの前に確かめる

- 図は `![w:1136](./figs/<デッキ名>-<図>-<段階>.svg)` で等倍で貼る。区切りの `---` の前に空行を入れる
- ページの種類は `<!-- _class: title / content / summary / bridge -->`
- まとめのページの項目は、台本のまとめと一字一句そろえ、`<br>` で行を切る

```bash
python3 <skill>/scripts/check_deck.py <デッキ.md>     # 空のページ・まとめの幅と行数・注記とページ・まとめの一字一句
```

通らなければ直してから次へ（ビルドして目で確かめる往復をしない）。

## 4. 台本を調整する

`references/consistency.md` の「スライドを作ったら、台本を調整する」を行う（ページを送る位置で文を区切る・📊 を振り直す・図にして見つかった内容の問題を直す）。
台本はユーザーのものなので、直したところと理由を最後に報告する。

## 5. 書き出して、自分で見る

```bash
python3 <skill>/scripts/build_slides.py <デッキ.md> --png <ページ画像の場所>          # PDF と、ページ画像
python3 <skill>/scripts/sheet_pages.py <ページ画像の場所> <並べた画像の場所>          # 4枚ずつ並べる
```

- ページ画像の場所は、デッキの場所の外（一時フォルダ）にする
- 図の検査の NG は直す。「注釈」「候補」の行は1行ずつ見て、当たりだけ直す
- 並べた画像で全ページを見る（文字どうしの重なりと色は検査に出ない。`references/figures.md` の「目で見ること」）

## 6. レビュー（推奨）

書き手と別のエージェントにレビューさせる。プラグインとして入れていれば `slide-reviewer` エージェントがある。
依頼する前に `python3 <skill>/scripts/build_slides.py <デッキ.md> --verify --png <ページ画像の場所>` を通し、
依頼文にページ画像と並べた画像の場所を書く。直したあとの再確認は、同じレビュアーに続きを頼む（毎回新しく起動すると、規則と全ページを読み直すぶん高くつく）。

## 作業の型（トークンを節約する）

- 1つのセッションで作るデッキは1本にする（続けると文脈が膨らみ、後半の1手が高くつく）
- 自分で書いたファイルを、確かめるためだけに読み直さない
- 文字の幅を目やソースの数字で見積もらない。検査で測る
