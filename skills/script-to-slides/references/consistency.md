# 台本とスライドの整合性

スライドは「台本を読み物にしたもの」ではなく、**台本を話しているときに映す補助資料**。この前提で、文字と図とでルールが違う。

## 文字は台本から導く

- 見出し・文字の主張・数値は、すべて台本から導く。台本にない概念・数値を文字として足さない。
  足したくなったら、先に台本を直してからスライドを直す。
- 台本に具体的な例文があれば、スライドでもその例文をそのまま使う（別の例に差し替えない）。
- 引用の形の発話（吹き出し・画面の文言）、固有名、数値は台本どおりにする。台本にない発話を吹き出しに作らない。
- まとめのページは、台本のまとめと**一字一句**そろえる（`check_deck.py` が照合する）。

## 図は台本より詳しくてよい（ただし正確に）

- 仕組みを正確に伝えるためなら、台本が語っていない補助的なステップ・関係の矢印・伏せ字（`？？？`）・版の表記を図だけに足してよい。
- 図の内容は事実として正確にする（不正確な単純化をしない）。
- **含みを落とさない。** ラベルに縮めると「など」「たとえば」「〜ことがある」「この場合」「または」が落ちて、言い切りや網羅に読める。
  段階に割るときは、含みと注記を1段階目から出す。番号つきの一覧の図は「それで全部」に読めるので、台本の含み（「代表的な」等）を小見出しに出す。
- **限界と、そのあとの行動を落とさない。** 対策の図に、限界だけ・効能だけを残さない。
- 架空の名前（製品名・パッケージ名など）は「※ ○○は架空」を最初に出すページから添える。実在しないことを確かめる。
- 台本に AI への指示文などの「そのまま使う文」があるページは、一字一句そのまま載せる（但し書きも落とさない）。

## 📊 注記（台本とページの対応）

台本の、ページを送る位置に注記を置く:

```
📊 P<通しページ番号> — <見出し>（n/m）
```

- （n/m）は「同じ見出しの n 枚目／全 m 枚」。1枚だけの見出しには付けない。
- 「注記の数＝ページ数、P1 から欠番なく昇順」を保つ。見出し・（n/m）と合わせて `check_deck.py` が照合する（手で対応表を作らない）。
- **ページを送る位置は文の切れ目にする。** 文の途中になるなら、台本の文を区切る。

## スライドを作ったら、台本を調整する（毎回の工程）

スライドを作ると、台本の直すべき点が見つかる。作ったあとに、毎回この工程を行う。

1. 台本の段落とページの対応を見る（`check_deck.py --table`）
2. ページを送る位置が文の途中に来るところは、文を区切る
3. `📊` 注記を通しページ番号に振り直し、`check_deck.py` で照合する
4. 図にして見つかった内容の問題（原因と対策の対応の抜け、限界に触れていない等）を直す
5. 台本の語を直したら、同じ語を載せているページ（まとめ・図の行名）も合わせる

文を区切るときの注意:

- ページを送った直後の文頭に、接続詞に聞こえる指示語を置かない（「それと」→「そのファイルと」）
- 区切っても「〜ことがあります」「でも」「たとえば」の含みは、元の文と同じ強さで残す
- 前提の文は、画面に映っているものを指す言い方にする（架空の名前を映しているのに「思い浮かべてください」と言わない）
- 指示語を主語に置き換えたら、述語も合わせる。次の文の指示語の指す先が飛んでいないかも確かめる

## 台本の書き方（道具が読む形）

道具（`check_deck.py`）が読むのは、次の3つだけ。ほかは自由に書いてよい。

- `📊 P<番号> — <見出し>（n/m）` の注記の行（1枚目は `📊 P1 — <タイトル>（タイトル）`）
- `## まとめ` の見出しと、その下の `1つ目、…`・`2つ目は、…` で始まる項目（デッキのまとめのページと一字一句照合する）
- 注記から次の注記までの、読み上げる文の字数（1ページに読み上げが多すぎないかの目安に使う）

見本は `examples/hand-drip/talk.script.md`。
