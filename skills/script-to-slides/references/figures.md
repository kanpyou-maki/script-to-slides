# 図解主体のスライドと、図の規則

## 原則

- **内容のページは「見出し＋図1つ」にする。** 台本の文を箇条書きで載せない。
  文字が主役でよいのは、タイトル・まとめ・橋渡し・聞き手への指示・デモの合図だけ。
- **仕組みの図は1ページで完成させない。** 同じ図を2〜3ページに割って、要素を足していく（段階表示）。
  1ページで新しく出す要素は、読み上げ1〜2文ぶんにする。Marp のままでできる（同じ見出しのページを続ける）。
- 図にする関係がない段落は、台本の語句を大きく1〜2行で置く。箇条書きには戻さない。
- カードやパネルを並べる型を全ページで繰り返さない。内容の関係（対比・時系列・包含・照合）に合う型を選ぶ。

## 段階表示

- 段階のあいだで、共通の要素の位置を動かさない。途中で消してよいのは、役目を終えた要素だけ。
- 図の中の見出し・矢印も、台本でその語が出るページから出す（先に出すと、矢印が何もない場所を指す）。
- 図は `<デッキ名>_figs.py` に、段階の番号を受け取る関数として書く（見本は `examples/hand-drip/talk_figs.py`）。

## 図の規則

### 箱と文字

- 箱の中は大きめの**1行ラベル**（28px）。名前＋説明の2段組みにしない。説明は口頭で言う。
- 強調は太い枠ではなく**ベタ塗り**。主役以外は薄く落とす（`dim()`）。
- 人物・アプリ・AI・データベース・サーバーなどは、「ユーザー」と書いた箱ではなく**絵**で描く（`figlib.py` の部品）。
- 要素は足すより大きくする。濃い文字のかたまりは、初めて出す図で7個程度、積み上げた最終段で12個程度まで
  （2行のラベルは1個。薄くした要素は数えない）。超えたら、役目を終えた要素を薄くするか消す。それでも超えるなら図を分ける。
- **文字サイズ**（1280×720）: 図のラベルは28px以上。注釈（「※…は架空」「または」）は19px以上。主張を担う語を注釈サイズにしない。
- 箱に添える説明は「例：〜」の短い形（24px）。台本の1文を長い1行で載せず、残りは口頭で言う。
- 図の中でいちばん大きい文字は、台本の語にする（図のために足した架空名・伏せ字を主役にしない）。
- 右下の隅はページ番号が来るので空ける。

### 矢印と線

- 矢印の向きはデータ・処理の流れ、ラベルは動詞にする。
- **矢印1本に動詞1つ。**「見つけて使う」は「見つける」「使う」の2本に分ける。ラベルを省くのは、前後の絵と箱から読める短いつなぎだけ。
- 矢印でつなぐと順番に読める。順番のない2つ（範囲の線引き・対比）は、境界線で分ける。
- 対応のない2組（窓の中の行と、並べた矢印等）の高さをそろえない（行ごとの対に読める）。
- 線でつなぐとき、否定・条件の要になる語（「しない限り」等）を線のつながりの外に置かない（箱だけをたどると逆に読める）。
- 矢印と同じ色の注記を、矢印の起点のすぐ上・下に置かない（矢印のラベルに読める）。注記は、それが説明する部品の横に置く。
- 図の読む向き（左から右）と、台本で語が出る順をそろえる。

### 否定の書き方

- 否定（しないこと・できないこと）を、肯定の見出しの下に同じ形の箱で並べない（目指すものに読める）。否定の印（`cross()`）を大きくし、箱の手前に置く。
- **「×」のうしろは肯定形の名詞にする。**「必要ない」に×を付けると二重否定に読める。否定の小見出し（「必要ないもの」）を置き、×のうしろは名詞で書く。
- **部品の説明・別名は、その部品の列に置く。** 薄くした別の部品の真下に置くと、そちらの説明に読める。

### 色

既定の割り当て（`figlib.py` と `theme.css` の色。デッキの内容に合わせて変えてよいが、**1つのデッキの中で意味を変えない**）:

| 色 | 意味 |
|----|------|
| 赤 | 問題・危険な状態・失敗 |
| 緑 | 正しい・安全・成功 |
| 青 | 聞き手（自分）・聞き手が使うもの |
| 紺 | 仕組み・道具の働き・確認・事実の説明 |
| 灰 | 中立・背景 |

- 「これから確かめる項目」に赤や緑を使わない。道具の限界（「できない」）や事実の説明も紺で、赤は問題の状態だけ。
- **色は、箱が何について言っているかで決める。** 性質を並べる箱は主語の箱と同じ色に、箱の上の小見出しは箱と同じ色にする。
  箱へ続く前置き（「たとえば、」「〜と同じで」）と、箱に続く語（「だけ」「までできる」）も、箱と同じ色。
- 同じ語を、ページによって別の色にしない。

## 機械の検査と、目で見ること

`build_slides.py` は、図を書き出したあと SVG をブラウザで描画して実測する（`check_figs.mjs`）:

- 箱の縁まで14px以上、viewBox の外に出ない、19px未満の文字がない、右下の隅に文字がかからない
- 28px 未満の文字は「注釈」の行で1件ずつ出る。意図した注釈だけかを確かめる
- 差分のハイライトのように、文字を重ねるのが意図の矩形には `data-hl="1"` を付ける
- 文字の幅をソースの数字から見積もらない。検査で測り、収まらなければ「文言を短くする → 箱を広げる」の順で直す

検査に出ないもの（目で見る）:

- 文字どうしの重なり・接触（測るのは文字と箱の余白だけ）。`sheet_pages.py` の並べた画像で全ページを見て、ラベルが隣り合うところは1枚ずつ拡大して見る
- 色。同じ語が別の色の箱に入っていないかを、次の検索で一覧にして見る:
  `grep -hoE 'box2?\([^"]*"[^"]+"(, *"[^"]+")?, *[A-Z_]+' <デッキの場所>/*_figs.py`
- 「候補」の行（`build_slides.py` が `_figs.py` のソースから出す）は、当たり外れがある。1行ずつ見て、当たりだけ直す
